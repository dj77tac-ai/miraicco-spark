# Spark 電子ブック

みらいっこの季刊誌 **Spark** の PDF を、保護者がスマートフォンやパソコンで
「ページをめくるように」読めるようにする仕組み。

- 公開URL： https://dj77tac-ai.github.io/miraicco-spark/
- リポジトリ： `dj77tac-ai/miraicco-spark`

有料サービス（FlipBuilder・年 $99）の代わりに作ったもの。
**費用はかからず、支払いが止まって突然読めなくなることもない。**

---

## 何をしているのか（しくみ）

1. PDF を1ページずつ画像に変える
2. その画像を**パスワードで暗号化**して `docs/d/` に置く
3. 置き場所（GitHub Pages）は誰でもアクセスできるが、
   ファイルの中身はパスワードなしでは**ただの意味のないデータ**にしか見えない
4. 保護者がパスワードを入れると、**そのブラウザの中だけで**画像に戻して表示する

サーバー側に仕掛けが要らないため、無料の置き場所だけで動く。

### 大事なこと

- **パスワードは暗号化そのものに使われている。** 画面をごまかして通り抜ける、
  ということができない作りになっている
- ただし、暗号化されたファイル自体は誰でも手に入る。
  **パスワードが短かったり、よくある単語だったりすると、時間をかければ破られる。**
  12文字以上・辞書に無い言葉を混ぜたものにすること
- パスワードを変えると**全部作り直し**になる（`build.mjs` が自動で気づいて作り直す）

## ファイルの置き場所

| 場所 | 中身 |
| --- | --- |
| `config.json` | 号の一覧（**並び順もここで決まる**）と、元PDFを探すフォルダ（Google ドライブ） |
| `password.txt` | パスワード。**git に入らない**（`.gitignore` 済み） |
| `build.mjs` | PDF → 画像 → 暗号化 をする道具 |
| `公開する.command` | **ダブルクリックで公開。ふだんの入口** |
| `publish.mjs` | その中身。号の追加を対話で聞いて、作り直して公開する |
| `公開のしかた（立川さん用）.md` | ふだんの作業の手順（2分） |
| `広報チームへのご案内.md` | 広報チーム向け。ドライブへの入れ方と、保護者への伝え方 |
| `めくる音のつくりかた.md` / `.py` | めくる音の作り方（**いまは使っていない**。戻したくなったとき用） |
| `別のパソコンで使えるようにする.md` | パソコンを替えたときの1回だけの準備 |
| `docs/` | **これが公開される。** 画面のプログラムと暗号化ずみのデータ |
| `docs/d/` | 暗号化された本文（`build.mjs` が作る） |
| `work/` | 変換の途中で使う場所。作業後に自動で消える |
| `.buildstate.json` | 前回どのパスワードで作ったかの控え。手元だけ・git に入らない |

> `docs` という名前なのは、GitHub Pages が「リポジトリ直下」か「docs フォルダ」しか
> 公開できないため。説明書ではなく**公開されるサイト本体**が入っている。

## 元データはどこにあるか

**広報チームがすでに使っている Google ドライブの共有フォルダをそのまま読んでいる。**
新しく置き場所を作る必要はない。

```
マイドライブ / WORK / ★SBフォルダ / ★共有フォルダ / 99お知らせ / ブログ関連 / Spark /
```

この下が号ごとのフォルダ（`202407` `2025_101112` `2026123` …）になっていて、
それぞれの `成果物` フォルダに完成した PDF が入っている。
`config.json` の `pdfDirs` がこのフォルダを指しているので、
`pdf` にはここからの**相対パス**を書く。

```json
{ "id": "202601_03", "label": "2026年1〜3月号", "pdf": "2026123/成果物/Spark-Jan-Mar -Ol.pdf" }
```

### どの PDF を選ぶか

1つの号に何種類も PDF が入っていることがある。選ぶ順番は、

1. `アーカイブ` / `ForArchive` と付いているもの（**閲覧用に作られたもの。これが最良**）
2. `-Ol` / `ForWeb` と付いているもの（オンライン用。トンボ付きのことがある）
3. `入稿用` は選ばない（印刷所へ出すためのもの）
4. **`(進捗◯◯)` と付いているものは絶対に選ばない**（制作途中の下書き）

> **2026-09-02の失敗。** 2025年1〜3月号に `(進捗14)Spark -Jan Feb Mar.pdf` を
> 使っていた。号のフォルダ直下にあり目につきやすいが、これは制作途中の下書きで、
> 見開き（A3横）のまま書き出されていた。正式版は
> `2025_123/2025_123最終データ/Spark -Jan Feb Mar-Archive.pdf`。
> **成果物／最終データのフォルダの中を必ず見ること。**

> 2025年10〜12月号と2026年1〜3月号は、`ForArchive` という名前のファイルが
> **0バイト（アップロードに失敗した空ファイル）**だったため `-Ol` を使っている。
> 広報チームが入れ直してくれたら、そちらへ切り替えるとよい。

### 号によって PDF の作り方が2通りある（両方とも自動で吸収する）

| 作り方 | どの号 | どうしているか |
| --- | --- | --- |
| たて1ページずつ | ほとんどの号 | そのまま使う |
| **見開き（A3横＝2ページ分が1枚）** | **2025年1〜3月号だけ** | **まん中で切って、左→右の順に2ページにする** |

2025年1〜3月号は「表紙(A4) + 見開き×5(A3) + 裏表紙(A4) = 7枚」で入っていた。
そのまま出すと横に長い紙が1枚ずつ出てしまうので、`build.mjs` の `facePlan` が
A4の2倍幅のページを見つけて半分に切っている（7枚 → 12ページ）。

**新しい号を入れたら、ページ数が想定どおりか必ず見ること。**
見開きで作られていると枚数が半分ほどになる。

### トンボ（印刷用の目印）は自動で切り落とす

`-Ol` の PDF には、四隅にトンボと外側の余白が付いていることがある。
そのままだと紙のまわりに白いふちと十字の線が見えるので、
**A4 より大きい PDF は自動で A4 の大きさに切り落とす**（`build.mjs` の `facePlan`）。
切り落としたときは作成中に `[トンボを切落し ◯枚]` と出る。
切り落としてほしくない号は `config.json` にその号だけ `"trim": false` と書く。

## 新しい号を出すとき

**`公開する.command` をダブルクリックするだけ。**（中身は `publish.mjs`）

質問に答えると、config.json への追加・作り直し・公開まで全部やる。

1. ドライブに新しい号のフォルダがあるか探す
2. その中の PDF を並べて見せ、どれを使うか選ばせる
   （`アーカイブ`/`ForArchive` → `-Ol`/`ForWeb` → その他 → `入稿用` の順に上へ出す。
   0バイトのファイルは「中身が空です」と警告して選ばせない）
3. `y` を選ぶと PDF を Preview で開き、中身を目で確かめられる
4. フォルダ名から号の名前を考えて出す（`2026456` → `2026年4〜6月号`）。Enter でそのまま採用
5. `config.json` に書き足して、`build.mjs` を動かす
6. **`yes` と打たせてから**公開する（`y` では通らない）

**この作業は立川さんが行う**（2026-09-02の判断。広報担当に GitHub を触らせると
かえって煩雑になるため）。広報チームはドライブに PDF を入れて一言伝えるだけ。
別のパソコンでも公開できるようにする手順は `別のパソコンで使えるようにする.md`。

> `git pull --rebase` を先に走らせているので、複数人が別々に出しても壊れない。

## 並び順を変えたいとき

**`config.json` の `issues` の並びが、そのまま順番になる。**

- 上ほど古い号、**いちばん下が最新号**
- いちばん下の号が、一覧のいちばん上に「最新号」として大きく出る
- 残りは新しい順にならび、`id` の先頭4桁の年ごとにまとめて表示される
- 号の名前（`label`）を直したいときも、ここを書き換えて `node build.mjs` → `git push`

並べ替えや名前の変更だけなら、PDF を作り直さないので数秒で終わる。

## 画面の作りかた

- `docs/index.html` … 3つの画面（パスワード／一覧／読む）
- `docs/app.js` … パスワードの確認・暗号を戻す・ページめくり
- `docs/style.css` … 見た目。色は先頭の `:root` にまとめてある
- `docs/vendor/page-flip.*` … ページめくりの部品（[page-flip](https://github.com/Nodlik/StPageFlip) 2.0.7・MIT ライセンス）

`app.js` や `style.css` を直したら `node build.mjs` を実行すること。
`index.html` の中の番号が付け替わり、保護者のブラウザが古いものを使い続けるのを防ぐ。

### page-flip に1か所だけ手を入れてある

もとの page-flip は、毎回いちばん下を**白でぬりつぶして**から紙を描いていた。
そのため表紙を1枚だけ出すとき、**隣に白い紙が見えてしまう**。
`docs/vendor/page-flip.browser.js` の `clear()` を「透明でぬる」に変えて直してある
（ファイルの先頭にも書いてある）。**部品を新しくするときは、この変更も入れ直すこと。**

## 決めたこと・注意

- **画像は 150dpi・JPEG 品質 82。** A4 で1ページ約 400KB。
  もっときれいにしたい場合は `config.json` の `dpi` を上げる（そのぶん重くなる）
- **表紙と裏表紙は1枚だけで出し、画面の中央に置く**（`app.js` の `centerLonePage`）
- **一覧は古い順（左から右へ進むほど新しい号）。**最新号だけは上に大きく出す
- **一覧は「木の本棚」の見た目**（2026-09-02・立川さんが3案から選択）。
  表紙の下に木の棚板（`.plank`）が通る。
  **棚は本のある所にだけ置く。**板は1冊につき1枚で、左右に半分ずつはみ出させて
  となりの本の板とつなげている（`margin: 0 -10px`／せまい画面では `-7px`）。
  一度「行いっぱいに伸ばす」形にしたが、**スマートフォンで本のない所に
  棚だけが残ってバランスが悪かった**ため戻した（立川さんの指示）
- **号ごとに版番号を持たせている**（`manifest` の `v`）。作り直したときに、
  前に見た人のブラウザが古い画像を使い続けるのを防ぐため。
  実際に、7ページだった号を12ページに作り直したとき、後ろの5ページが
  出てこないという事故が起きた（2026-09-02）
- **パスワードは端末におぼえさせている**（`localStorage`）。
  一度入れれば次からは入れ直さなくてよい。「とじる」を押すと忘れる
- **めくる音は鳴らさない。**一度入れたが「耳障りになる」ため外した（2026-09-03・立川さんの判断）。
  音を作る道具は `めくる音のつくりかた.md` / `.py` に残してあるので、
  戻したくなったときは作り直せる（`docs/flip.wav` と `app.js` の再生部分を足す）
- 検索に出ないよう `robots.txt` と `noindex` を入れてある
- ぜんぶ作り直したいときは `node build.mjs --force`
- **A4 より大きい PDF は自動で A4 に切り落とす**（トンボ対策）。`"trim": false` で止められる
